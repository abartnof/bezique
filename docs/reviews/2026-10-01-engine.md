# Code review of the engine, 2026-10-01

A review at the most thorough setting of `crates/bezique-core` and the
documents' claims about it, covering commits `bd3bdd6..a70f478`. Fifteen
findings were reported, and five more were confirmed but cut for space. Each
was reproduced by the reviewer with a scratch test before being reported.

Each finding is labelled:

- **defect**: contradicts a rule, a document or the code's own contract;
- **latent defect**: wrong, but not reachable through the moves the engine
  offers today;
- **document**: the code is right and the text is wrong;
- **test**: a test weaker than it claims;
- **preference**: a better way, not a fault.

| # | Finding | Label | Resolution |
|---|---|---|---|
| 1 | Twins leak hidden cards. Move generation always lays or plays the lower concealed copy, so which copy appears says where its twin is. `Hand::known` tracks seen cards by copy, so after a player plays the unseen twin of a seen card, the opponent's view still shows the seen card. | defect | fixed: knowledge of concealed cards is counted by type; views renumber the twins a player never held from what is visible (a lone copy is copy 0); in the last eight tricks the other's declaration record keeps types only. Tested on every position of random games. DESIGN §5 rewritten. |
| 2 | `Card`, `Suit` and `Rank` are public `u8` newtypes with no range check. `Play(Card(64))` panics in debug and plays the aliased `Card(0)` in release; a `Declare` naming `Suit(4)` panics. | defect (API) | fixed: `Card`, `Suit`, `Rank` and `Meld` gain `is_valid`; `Hand::apply` and `Holdings::check` refuse what names nothing, before using it |
| 3 | `Action::Dix` is checked against the twin-deduplicated list, so the upper copy of a seven of trumps is refused with a false reason. | latent defect | fixed: any concealed, unscored seven of trumps is accepted; only the list of moves is deduplicated |
| 4 | `Hand::arranged` validates nothing and resets the record of sevens scored: odd stocks panic mid-move, wrong trick counts end the hand wrongly, a rebuilt hand lets a seven score again. | defect (API) | open |
| 5 | `best_riders` keeps the first maximal set, so a free rider always takes the lower twin even when that twin already guards a carried score; and it silently drops riders past the sixteenth. | preference / latent defect | open |
| 6 | When a side reaches 1,000 mid-hand the hand stays live: `game.hand().to_move()` is still a seat, and `View::my_turn()` is true in a finished game. | defect | open |
| 7 | `Hand::legal` returns the curated announcements in the declare phase while `apply` accepts any `check`-legal one; its doc ("every move open") and DESIGN §6.2 ("agents and tests see all of them") are false. | document | open |
| 8 | `Game::arranged` accepts a finished hand (a game neither over nor playable), and restarts the deal stream, so the next hand repeats `Game::new`'s first deal. | defect (test API) | open |
| 9 | DESIGN §5's dedupe and search key, (type, location, history), is unsound: twins with equal histories can differ in which carried score they guard. | document | fixed: DESIGN §5 keys table cards by type, history and carried-score membership |
| 10 | PLAN credits the deal-odds test with catching a naive shuffle; it passes the textbook naive shuffle and Sattolo's algorithm, and caught the planted variant by 0.1 standard errors. | document / test | open |
| 11 | The invariant "the log reconciles with the totals" compares the same sum with itself; and the three invariant tests replay the same streams, so "4,500 hands" are 2,000 distinct ones. | test | open |
| 12 | The chi-square cutoff 28.3 is documented as the 1-in-100,000 value for five degrees of freedom; it is that for four. For five it is 30.86. | document | open |
| 13 | The doc of `DEALS` says the cut and the agents have streams of their own; nothing defines them. | document | open |
| 14 | RULES.md calls twins "identical in every respect", against its own rule 3; and cites "double bezique must have all four cards on the table at once" to Foster, though it is Cady's (Rubicon, p. 20, applied to the ordinary game by p. 15). | document | open |
| 15 | `Game::previous_hand` is documented as the hand finished most recently, but when the game ends on a hand's last trick that hand stays in `hand()`. | document | open |
